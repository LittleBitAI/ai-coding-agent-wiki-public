# 서브에이전트를 임의로 늘리지 않는다

규칙. 사용자가 명시적으로 요청하지 않았다면 `spawn_agent` 같은 하위 에이전트·하위 세션을
절대 생성·호출·재개하거나 재위임하지 않는다. 하위 워크트리를 만들어 에이전트를 붙이는
방식으로 우회하지 않는다. 같은 작업공간에 나란히 둔 별도 작업·리뷰 셀은 이 금지 대상이 아니다.

- 구현과 독립 리뷰는 서로 다른 Codex 셀에서 한다. 구현 셀의 자체 검사를 독립 리뷰로
  대체하지 않는다. 사용자가 만든 리뷰 셀을 유지하고 기존 리뷰 셀을 우선 재사용한다.
- 같은 작업공간에 필요한 별도 셀을 생성하는 것은 허용된다. 이 허용을 하위 에이전트 생성
  허가로 확대하지 않는다. 불필요하게 셀을 늘리지 않는다.
- 하위 세션 정리 요청으로 독립 리뷰 셀을 닫지 않는다. 리뷰 종료만으로 사용자가 마련한
  리뷰 셀을 없애지 않는다.
- 문서의 리뷰 절차, 도구의 존재, 속도 개선 판단은 하위 에이전트 사용 허가가 아니다.
  이전 과업에서 하위 에이전트를 허용했어도 다음 과업으로 그 허가를 확대하지 않는다.

어겼을 때. 불필요한 세션과 맥락 전달·결과 회수 비용이 늘어나고 작업 책임이 분산된다.

작업 종류에 상관없는 규칙이므로 비어 있지 않은 모든 사용자 발화에 주입한다. 주입은 도구
차단기가 아니다. 하위 에이전트 허가는 사용자의 명시적 요청으로 판단한다.

## 셀이 여럿이면 어느 셀이냐도 정해져 있다

셀을 안 늘리는 것과, 있는 셀 중 **맞는 것**에 보내는 것은 다른 규칙이다.

| 일 | 어디로 |
| --- | --- |
| 코드 수정 · 코드 리뷰 | **sol** |
| 어려운 문제 — 재분석, 논문 조사, 막힌 설계의 인수인계 | **astra** |

astra 에 코드 리뷰를 맡기는 것은 **자원 낭비다.**

셀 목록에서 모델이 안 보이면 `orca terminal list` 의 preview 를 봐라. 모델은
셀 생성 옵션이 아니라 Codex 세션 안에서 고르는 것이라, 제목만으로는 안 갈린다.
어느 셀이 sol 인지 확실하지 않으면 라운드를 보내기 전에 사용자에게 묻는다 —
[[ask-with-arrow-key-options]]. 잘못 보낸 라운드는 비싼 모델의 시간을 쓰고도
리뷰 루프에는 아무것도 안 남긴다.

## 라이브 회차가 여럿이면 다 돌린 뒤에 보낸다

회차 하나가 끝날 때마다 라운드를 준비하지 않는다. 실패가 간헐적인 변경은 회차
하나로 아무것도 못 말하고 — 5회 중 1회 나는 실패라면 초록 한 번은 수리의
증거가 아니라 안 걸린 회차다 — 그 상태로 쓴 지시문은 리뷰어에게 없는 근거를
준다. 회차를 다 돌리고, 결과를 다 적고, 그다음에 보낸다.
