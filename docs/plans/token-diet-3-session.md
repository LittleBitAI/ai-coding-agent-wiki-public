# 3묶음 — 세션 운영 (7~8단계)

전체 설계와 단계 표는 [개요](token-diet.md)에 있다. 7단계의 측정은 [1묶음](token-diet-1-hook.md)의
`replay` 가 한다.

목표. 세션을 오래 두었다 돌아올 때 문맥 전체를 캐시에 다시 쓰는 값을 줄인다. 만들기 전에 그런
복귀가 실제로 얼마나 있는지부터 잰다.

## 2026-09-25 구체화에서 정한 것

| 질문 | 고른 것 |
| --- | --- |
| keep-alive 범위 | 측정 먼저. 이득이 보이면 Orca 셀부터 구현 |
| 과금 | 구독(Pro/Max). 셈은 돈이 아니라 사용 한도로 적는다 |
| 운영 규칙 페이지 | `operator` 의 `contract`, 좁은 트리거 |

같은 날 확인한 사실. 이 PC 의 Claude Code transcript 는 캐시 쓰기가 전부 `ephemeral_1h_input_tokens`
이고 `ephemeral_5m_input_tokens` 는 0 이다. 1시간 캐시라는 전제가 이 환경에서는 맞다. 이 저장소의
한 세션은 `preTokens` 967,131 에서 자동 compact 됐고 155초가 걸렸다 — 세션이 1M 문맥 끝까지 간다.

## PR 과 단계

7·8 은 1묶음 PR ① 의 측정이 나온 뒤에 정한다. 측정이 7단계를 접으면 PR 은 8단계 하나다.

## 7단계 — 측정 먼저

### 셈

문맥 크기를 C 토큰이라 하자. API 요율(쓰기 2배, 읽기 0.1배)을 한도 소모의 대리값으로 쓴다.
구독 한도에서 캐시 읽기가 얼마로 세어지는지는 공개되지 않았으므로, 이 셈은 추정으로 적는다.

| 경우 | 핑 없음 | 핑 k번 |
| --- | --- | --- |
| 60분 뒤 돌아온다 | 2C (다시 쓰기) | 0.1C × (k + 1) |
| 안 돌아온다 | 0 | 0.1C × k (전부 손해) |

60분 안의 복귀는 캐시가 살아 있어 핑이 필요 없다. 55분마다 핑 k번이면 60 + 55k 분 안의 복귀를 구한다.

### `replay` 가 내는 것

- 세션마다 이어진 두 행의 간격. 60분 미만 / 60~115분(핑 1번이면 구함) / 115~170분(2번) /
  170~225분(3번) / 225~280분(4번) / 그 이상 또는 복귀 없음
- 복귀한 턴의 문맥 크기. transcript 에서 복귀 직후 첫 응답의 `usage` 의
  `cache_creation_input_tokens` 를 읽는다. 그 값이 실제로 다시 쓴 양이다
- 위 표로 상한 1~4번 각각의 순절감 추정. 두 저장소, 측정 기간 전체

### 결정

수치가 나오면 `AskUserQuestion` 으로 묻는다. 선택지는 "상한 N 으로 구현", "안 한다" 이고 각각의
순절감 추정과 손해 추정을 설명에 싣는다. 이 문서에는 그 수치와 답을 적는다.

### 구현할 때의 모양 — 결정이 "한다" 일 때만

- 대상은 Orca 셀뿐이다. 핑은 `orca terminal send` 로 넣는다. 그 밖의 호스트는 경로가 확인될 때까지 보류
- 5단계 데몬이 타이머를 겸한다. 세션별 마지막 턴 시각은 trajectory 의 `at` 에 이미 있다.
  세션과 Orca 터미널을 잇는 방법(`orca terminal list` 의 무엇으로 짝을 짓는가)을 착수 때 먼저 확인한다
- 핑 문구는 고정한다. 예: `keep-alive — reply "ok" and nothing else.`
  `inject.py` 는 이 문구와 정확히 같은 발화에는 아무것도 싣지 않고 trajectory 에도 적지 않는다.
  `declared_continuation` 같은 `Stop` 훅이 이 턴에 반응하지 않는지도 본다
- 세션당 상한은 결정에서 고른 N. 사람이 발화하면 계수가 0 으로 돌아간다
- 데몬의 유휴 종료(3시간)는 핑 타이머가 도는 동안 미뤄진다. 상한에 닿으면 타이머가 풀리고 유휴 시계가 다시 간다

## 8단계 — 운영 규칙 페이지

`operator/compact-before-idle.md`, `severity: contract`. 허브 페이지라 본문은 영어다.

담을 것.

- 오래 자리를 비우기 전에 `/compact`. 돌아와서 다시 쓰는 양이 C 에서 compact 요약 크기로 준다.
  이 저장소의 실측은 967K → 11K 였다
- 자동 compact 문턱. Claude Code 와 Codex 각각 어느 설정으로 바꾸는지 — 설정 이름은 페이지를
  쓸 때 설치된 버전의 문서에서 확인하고 적는다. 추측한 이름은 쓰지 않는다
- keep-alive 가 언제 이득인가. 7단계의 셈과 실측 수치. 7단계가 접혔으면 "왜 안 하는가" 로 적는다

트리거. `compact`, `퇴근`, 그리고 토큰 이야기. "토큰" 한 단어는 인증 토큰에도 걸리므로
`토큰.{0,8}(아끼|절약|절감|많이|줄)` 처럼 좁힌다. 1단계 `replay` 로 오탐을 한 번 본다.
