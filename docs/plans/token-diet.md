# 토큰 절감 — 같은 규칙을 두 번 싣지 않고, 필요한 조각만 찾는다

목표. 작업 세션과 위키 챗이 쓰는 토큰을 줄인다. 조건은 하나다 — 훅이 느려지면
안 된다. 위키 챗은 느려져도 된다.

## 출발점 — 2026-09-25 실측

| 무엇 | 값 | 어디서 |
| --- | --- | --- |
| 같은 세션에 이미 실린 페이지를 또 실은 비율 | 624회 중 457회, 73% | 이 저장소 `.wiki/trajectory.jsonl` |
| 매 턴 실리는 상시 규칙 전문 | 약 9KB (`english-progress`·`agent-delegation`·`ask-with-arrow-key-options`) | 세 파일 크기 |
| 턴당 주입 크기 중앙값 / p90 (09-23 이후) | ai-nara-shop 12.4KB / 34.9KB, 이 저장소 8.6KB / 14.7KB | 각 저장소 trajectory `cost` |
| 훅 한 번의 시간 | 약 1.2초 = 파이썬 기동·import 0.17초 + 페이지 읽기·매칭 0.03초 미만 + 발화 번역 0.96초 | `inject.py` 직접 실행 3회 |

두 가지가 여기서 정해진다.

- 낭비의 대부분은 고르는 방식이 아니라 반복이다. 페이지가 50장 남짓이라 유사도 선택은
  무엇이 실리는지(리콜)를 바꾸지, 양을 크게 바꾸지 않는다.
- 12KB 를 넘는 주입은 호스트가 파일로 빼고 2KB 미리보기만 세션에 준다. 그런 턴에
  "전문을 실었다" 는 기록은 세션이 전문을 봤다는 뜻이 아니다. 중복 제거는 이것을 구분해야 한다.

페이지 번역은 이미 캐시된다 — `translate.py` 의 `raw/translate-cache.sqlite3`. 훅에서
시간이 드는 곳은 매번 새로운 발화의 번역뿐이고, 이번 범위에서 건드리지 않는다.

## 되돌리는 결정 — `SCHEMA.md` "What is not done" 의 임베딩 금지

그 줄은 임베딩이 네 가지 실패 지점을 더한다고 적었다. 이번 설계가 각각을 어떻게 막는지다.

| 실패 지점 | 이번 설계 |
| --- | --- |
| 키 | 로컬 ONNX 모델. 키 없음 |
| 네트워크 | localhost 만. 외부 호출 없음 |
| 쿼터 | 없음 |
| 낡은 벡터 | 청크 본문 해시로 색인. 본문이 바뀌면 그 청크만 다시 계산 |
| (새로 생기는 것) 데몬 프로세스 | 훅은 150ms 안에 답이 없으면 정규식만으로 진행하고 데몬을 띄운다. 데몬이 없어도 오늘과 같은 주입이 나간다 |

정규식 트리거는 그대로 권위다. 유사도는 정규식이 놓친 것을 한 줄로 덧붙일 뿐, 정규식이
고른 규칙을 빼지 않는다. `SCHEMA.md` 와 `index.md` 의 해당 문장은 5단계에서 이 내용으로 고친다.

## 고른 것과 고르지 않은 것

2026-09-25 사용자 선택. 고르지 않은 것도 적는다 — 다시 제안하기 전에 여기부터 읽는다.

| 축 | 고른 것 | 고르지 않은 것 |
| --- | --- | --- |
| 훅 양 | 세션 내 중복 제거, 스킬이 있는 규칙을 스킬로 | 상시 규칙 한 줄화, 모든 규칙 요약+포인터 |
| 선택 방식 | 정규식 + 유사도 보조 | 유사도로 대체, 오프라인 감사만 |
| 엔진 | 별도 경량 데몬 + 폴백 | 순수 BM25 in-process, model2vec, Gemini 임베딩 API |
| 임베딩 모델 | multilingual-e5 / bge-m3 계열 ONNX | — |
| 위키 챗 | 청크 하이브리드 검색, 그래프 1-hop, 싼 모델 1차 탐색 | LightRAG 식 엔티티 그래프 |
| 번역 | 페이지 캐시 (이미 있음) | 번역 데몬화, 번역 시간 예산 축소 |
| 세션 운영 | compact 후 재주입, keep-alive 자동 핑, compact·문턱 운영 규칙 | 도구 출력 압축 훅 |

## 2026-09-25 구체화가 이 문서를 고친 것

위 표의 "고른 것" 은 그대로다. 코드를 읽고 질문한 결과, 방법이 바뀐 자리는 이렇다.

| 원래 | 바뀐 것 | 왜 |
| --- | --- | --- |
| 이미 본 페이지는 `shrink(hard=False)` | 본문에서 빼고 `rule_index` 줄에 "이미 실림" 과 경로 | 색인이 이미 첫 문장을 싣는다. `shrink` 는 `Rule.` 로 시작하는 한 줄만 잡아 문장이 잘린다 |
| compact 는 `SessionStart` 표지 행, Codex 는 이벤트부터 확인 | 두 호스트 모두 transcript 의 compact 기록으로 감지. `session_state.py` 는 안 고친다 | Claude `compact_boundary`, Codex `compacted` 를 실물로 확인했다. 보고 재주입은 지금 동작이 이미 한다 |
| 지뢰는 스킬로 옮기지 않는다 | `codex-review-loop`(지뢰)는 절차만 스킬로, 사고 설명은 페이지에 | 두 스킬이 이미 절차를 가져 페이지와 두 벌이다 |
| Codex 가 스킬을 안 읽으면 전문을 페이지에 | 설치가 Codex 스킬 폴더에도 링크 | 지금 링크는 `~/.claude/skills` 에만 있다 |
| BM25 는 한국어 bi-gram | 영어 단어 + 한국어 bi-gram, 질의는 원문 + 영어본 | 허브 페이지가 이제 영어다 |
| 문턱은 1단계 재생으로 | Haiku 가 라벨을 만들고 sol 이 검토하는 200턴 표본으로. `SCHEMA.md` 에 측정 라벨 예외 한 줄 | 재생에는 정답이 없다 |
| keep-alive 를 만든다 | 유휴 뒤 복귀 빈도를 먼저 재고, 수치를 보고 정한다 | 쓸 일이 없을 수 있다 |

## 이번 범위 밖

- 발화 번역의 시간(0.96초). 캐시가 불가능한 유일한 부분이고, 줄이려면 영어본을 포기하는 턴이 는다
- 도구 출력 압축(`PostToolUse`). 작업 중 토큰의 큰 몫일 수 있으나 이번에 고르지 않았다. 1단계 도구가 필요성을 보이면 다시 묻는다
